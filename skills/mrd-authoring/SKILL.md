# MRD 写作

只执行当前阶段计划分配的能力；新项目加载与版本交接遵循[六阶段协议](../../system/protocols/six-stage-product-workflow.md)；旧项目按冻结流程恢复。

## 输入
读取确认的需求与场景，以及本阶段业务建模子任务的交接。业务模型尚未就绪时先等待依赖，不自行补造结论。
## 成稿结构
产品定义与核心价值；目标用户和场景；业务角色、对象与能力；核心业务流程；范围与非目标；关键规则和限制；成功标准；证据、假设和开放问题。
## 约束
- 用业务语言解释范围，保留被否方向及原因，不写开发选型、字段级接口或工具执行过程。
- 每项范围能追溯到用户场景，每项成功标准能说明如何观察；避免把待验证假设写为需求证据。
- MRD 的职责是冻结本次产品边界；后续页面、交互和视觉分别由设计阶段确认，不抢先固定无依据的设计。
- 市场规模、竞品大全和商业模式不是固定章节，只整合阶段计划已安排的相关研究。
## 交付
输出 Markdown 正文、未决事项及给设计阶段的范围摘要；交由独立审查者检查业务完整性和范围一致性，用户确认后才作为下游基线。
