# 产品范围与技术边界

## 用途

本文档吸收自 magi-product `lead-pm-prompt.md` 的通用铁律,用于提醒 PRD 输出保持产品需求边界,不要滑入技术实现方案。

| 边界项 | ❌ 技术实现写法 | ✅ 产品需求写法 |
|---|---|---|
| 信号路径 | 前端通过 A 服务调用 B 服务,再由 C 服务写入 MQ。 | 用户提交后应在 3 秒内看到提交结果;若处理较慢,需展示处理中状态。 |
| 通信协议 | 使用 CAN/LIN/HTTP2/WebSocket 等协议传输状态。 | 页面状态需能及时反映设备/订单/内容的最新变化,异常时提供明确提示。 |
| 防抖位置 | 在前端按钮层做 500ms debounce,后端通过 Redis 锁兜底。 | 重复点击不得产生重复提交;用户应看到按钮处理中状态。 |
| 电机响应 | 电机响应时间必须小于 100ms。 | 用户触发控制后应获得明确反馈;若设备未响应,需展示失败原因和重试入口。 |
| 触觉反馈 | 调用系统 haptic API 触发 medium impact。 | 关键操作成功或失败时,可通过视觉/声音/触觉之一提供反馈,具体实现由设计与技术评估。 |
| 芯片选型 | 采用某型号芯片或 SoC 以满足性能。 | 功能需支持目标设备上的流畅使用体验,性能指标以用户可感知体验定义。 |
| 数据存储 | 使用 MySQL 表字段 X/Y/Z 保存配置。 | 用户配置需要被保存,下次进入时自动恢复;若保存失败,必须告知用户。 |

## 写作原则

- PRD 负责说明用户目标、业务规则、交互状态、验收标准。
- 技术方案负责说明架构、接口、存储、协议、性能实现。
- 当 PRD 必须表达约束时,优先使用用户可感知结果,而不是底层实现路径。

## 业务安全与内容安全

业务安全和内容安全是两条独立风险线，不应因为出现在同一活动或同一页面就混写。

| 风险线 | 覆盖对象 | PRD 必写 |
|---|---|---|
| 业务安全 | 权益、积分、资金、开奖、资格、库存、订单、排行榜奖励、补偿 | AC、异常路径、owner、对账或补偿口径 |
| 内容安全 | 评论、图片、笔记、帖子、举报、审核、屏蔽、下架、申诉 | 审核状态、处置策略、申诉或运营处理路径 |

若同一功能同时涉及权益和社区内容，应拆成两个子段或两条规则：一条处理权益/资金闭环，一条处理内容审核和运营处置。
