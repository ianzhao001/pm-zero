# PRD 终稿自检清单

## 来源与用途

本文档吸收自 magi-product `lead-pm-prompt.md` 模式 C 末尾自检清单,用于 `prd-forge` 在输出终稿前进行最后一轮质量闸门检查。

| # | 自检项 | 通过标准 |
|---|---|---|
| 1 | 收益预估是否量化? | 用户收益、业务收益、效率收益至少有一个可量化指标;如暂无数据,必须标注假设值与待验证方式。 |
| 2 | 用户价值依据是否标注 A/B/C/D/E 等级? | 关键价值判断均标注证据等级;D/E 级不得单独支撑重大决策。 |
| 3 | 有没有写信号路径 / CAN 波特率 / 电机响应时间? | 若出现技术实现细节,必须改写为用户可感知的产品约束。 |
| 4 | 前端交互说明是否包含位置 + 界面元素表 + 交互逻辑 + 前端异常? | 每个核心页面或模块都有元素表、触发条件、状态变化、异常处理。 |
| 5 | 验收标准是否是四要素表格? | 每条验收标准包含场景、前置条件、操作、预期结果。 |
| 6 | PRD 类型是否明确? | 标注功能型 / 策略型 / 修复型 / 架构型之一,并采用对应章节裁剪。 |
| 7 | 用户画像是否准确? | 目标用户、非目标用户、使用场景、核心痛点清楚;避免泛化为"所有用户"。 |
| 8 | 有没有 ASCII 框图? | 不出现 `┌ └ │ ├ ┬ ┴ ─` 等字符画结构;流程用 Mermaid,元素用表格。 |

## 输出前口令

在交付 PRD 前,执行者应显式写出:

> 已完成 PRD 终稿自检,未发现技术实现越界、证据等级缺失、验收标准不可测或 ASCII 框图问题。
