# PRD 反馈模式

评审后更新 PRD 时使用本文件。

## 1. 拆分评审意见

将每条意见归为以下类型之一：

- 结构调整；
- 业务规则变化；
- 截图/证据变化；
- owner 或开放问题变化；
- 文案清理；
- validator 失败。

## 2. 最小改动模式

当用户要求窄范围更新时，只编辑被点名的章节、表格或模块，以及直接依赖它的交叉引用。

## 3. 证据覆盖

若某模块没有截图：

- Evidence 列写 `待设计补图`。
- 开放问题表包含模块、缺失原因和 owner。
- Manifest 使用 `source: missing`。

## 4. 三态交付

保持输出状态可见：

- Draft：允许假设。
- Review：高风险模块已闭环。
- Archive：除非豁免，否则没有未解决事项。

## 5. 校验看板

生成文档后总结：

- 标题数量；
- 表格数量；
- 图片数量；
- 开放问题；
- manifest 状态；
- validator errors 与 warnings。
