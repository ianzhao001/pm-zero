## §16 视觉品质（Visual Quality Bar）

范围见[协议](../../../../system/protocols/six-stage-product-workflow.md)；旧项目按确认范围。

### §16.1 信息密度上限

- 单屏「主信息行」不超过 7 行；其余必须折叠到 Sheet、二级页或可展开模块。
- 单卡内文字段落不超过 3 段；超出时拆卡。

### §16.2 节奏与留白

- Neutral、非 source-led 概念稿可用一块明确留白稳定节奏；不得把固定 `80px` 当成跨品牌硬门。
- Neutral 双列卡可控制极端高度跳变；截图吸收、真实瀑布流和 context-backed surface 按素材比例自适应，不套用固定高度差阈值。
- 截图吸收或长 Feed 原型中，Feed-like surfaces 的底部留白不得由人工 `min-height`、spacer 或 blank block 产生；没有更多数据时滚动应停在最后一张卡片/最后一行内容附近。
- 品牌字号、行高、尺寸和间距由 DS Pack 固化，并纳入 computed style 验收。

### §16.3 状态可视化优先级

- 关键状态用 chip（如「品控通过」「已截止」），不用大色块。
- 进度类信息（任务进度、榜单名次、投注比例）必须有数值 + 视觉条，不能只有视觉条。
- 用户请求的空状态应提供清晰提示；线框可轻量占位，高保真须使用匹配资产或空态组件。

### §16.4 动效预算

- 单屏同时运行的动画 ≤ 3 个；超过必须串联，不并发。
- 入场动画总时长 ≤ 600ms；超过会显得迟钝。
- 庆祝彩屑只在「真正终态」触发：下单成功、兑换成功、榜单上榜；不在中间步骤滥用。

### §16.5 前端稳健性

- Icon 必须是可见 SVG/icon 资产，不能用空节点、emoji、CSS pseudo 元素或填充块顶替；Tab、工具栏和 icon button 是强制检查对象。
- 手机内部的固定栏、badge、浮层和快捷按钮必须在 `.phone-screen` 边界内渲染；任何横向溢出、负向定位漂移或底栏遮挡主操作都视为布局失败。
- 卡片、Tab、chip、utility row 等紧凑文本容器必须具备明确的换行、clamp 或截断策略；按钮长文案由 rendered-DOM validator 检查真实溢出。

### §16.6 图片资产真实性

- 高保真商品图、内容图、头像、媒体封面必须来自明确可用的用户资产、已登记预置库存或语义搜索结果，不使用随机生成的本地 raster 占位图。
- 选择搜索图片时先写清楚 slot 意图，再用产品名、品类、风格或场景关键词检索；不能只因为图片好看就填入无关资产。
- 交付 HTML 中每个高保真 `<img>` 必须有 `data-asset-id`，清单记录来源；库存绑定版本/路径/hash，检索记录query/source/relevance。
- exact product image 不可获取时，允许使用同品类搜索图，但必须同步调整卡片文案或在 manifest 中说明 fallback，不得让文案和图片互相矛盾。

### §16.7 排版纪律（真实 App 质感的第一来源）

- 手机内部 UI 只用固定 px 字号，禁止 `clamp()` / `vw` / `rem` 响应式字体造成字号跳变。
- 单产物可见 UI 字号收敛到一个明确阶梯（参考阶梯 `10-30px` 间取整数档），distinct 字号 ≤ 9 档。
- 字体族用系统栈（PingFang/system），不为手机内部导入外部展示字体；数字/价格可用本机 DIN/Helvetica fallback。
- 行高、换行、截断、可见行数与字号一起构成 typography footprint；复刻或迭代时整体对齐，不能只对字号。
- 内容卡标题 clamp ≤ 2 行、meta 单行截断是移动端内容流的默认节奏。

### §16.8 内容主导，Chrome 退后

- 商品图/内容图/头像承担页面视觉重量；顶栏、底栏、搜索框、分割线保持克制（白/浅灰 surface + 细分割线），不与内容争抢注意力。
- 图片主导的内容卡：图占卡片主要高度，文字压缩在图下；不用大块渐变、抽象色块或装饰性插画替代真实内容。
- 双列内容流卡高由图片比例 + 文本自适应，禁止统一卡高制造空白；视频内容用小型角标标记，不用大播放按钮压图。
- 信息密度贴近真实 App：足够的图文、价格、作者、入口模块；中英混排保留品牌真实感（英文品牌名保留原文）。

### §16.9 同屏一致性

- 同组卡片圆角必须统一；控件圆角与卡片圆角分组管理，不在同一组件组内混用两档。
- 同屏同类图标风格统一：一套线框（stroke-only）或一套填充，不混用；同栏图标尺寸与线宽一致。
- 同类交互标记（如点赞/收藏）同屏只用一种图形语言，不混用两种隐喻。
- 状态红/警示红只用于风险、破坏性动作与小面积 badge；主价格、主 CTA 用中性强色或品牌 accent（详见 `do-and-dont.md` 颜色纪律）。
