# Review Modes

范围校准：六阶段默认正常主流程；未请求的空态、异常态不构成缺陷或自动测试要求。用户明确纳入范围或旧项目已确认的状态才按下文维度审查。完整报告作为附件，用户入口先展示结论与关键证据。

## 来源

本文件蒸馏自 magi-product `reviewer-prompt.md` 的审查模式表,并按 pm-zero 5.3.1 的 skill 结构改写。

## 模式一:方案概要审查

| 项目 | 内容 |
|---|---|
| 审查对象 | idea / MRD / 方案概要 / 策略提案 |
| 输出重点 | 目标是否清楚、用户是否明确、范围是否收敛、证据是否足够、收益是否可验证 |
| 典型问题 | 目标客群过宽、痛点没有证据、收益预估没有来源、范围边界缺失、决策点未列出 |
| 推荐模板 | `templates/phase-1-review.md` |

## 模式二:Demo 审查

| 项目 | 内容 |
|---|---|
| 审查对象 | HTML Demo / SVG / Mermaid 交互稿 / 可点击原型 |
| 输出重点 | 交互链路是否完整、信息架构是否符合上游、关键状态是否覆盖、视觉是否一致 |
| 典型问题 | 主流程缺节点、弹窗不能关闭、空态/错误态缺失、页面层级比交互稿多、关键按钮无反馈 |
| 推荐模板 | `templates/phase-2-review.md` |

## 模式三:PRD 审查

| 项目 | 内容 |
|---|---|
| 审查对象 | PRD 终稿 / PRD 草稿 / 需求规格说明 |
| 输出重点 | 需求逻辑、界面元素表、验收标准、证据等级、产品与技术边界 |
| 典型问题 | 把技术实现写成产品需求、验收标准不可测、界面元素表缺属性、收益指标无来源 |
| 推荐模板 | `templates/phase-3-review.md` |

## 模式选择规则

- 用户明确说“审方案”时,默认进入方案概要审查。
- 用户明确说“审 Demo / 原型 / 页面”时,默认进入 Demo 审查。
- 用户明确说“审 PRD / 需求文档”时,默认进入 PRD 审查。
- 输入材料无法判断类型时,先请求用户确认审查模式,不要自行猜测。
