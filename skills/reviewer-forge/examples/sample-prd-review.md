# Sample PRD Review:后视镜调节 PRD

## 假设输入

一份后视镜调节 PRD,目标是在车机屏幕中增加后视镜角度调节功能。

## 使用模板

本示例使用 `templates/phase-3-review.md` 的 PRD 审查模式。

## 审查结果表

| 等级 | 位置 | 问题描述 | 改进方向 |
|---|---|---|---|
| 🔴 致命 | §2 用户价值 | PRD 声称“可显著降低驾驶风险”,但没有任何用户事故、误调或安全数据支撑,证据等级为 E。 | 降级为待验证假设,或补充 A/B 级证据后再作为核心价值。 |
| 🟠 严重 | §4 主流程 | 主流程只写“用户点击调节”,没有说明驾驶中/停车中两种状态的限制。 | 补四态交互规则,至少区分驾驶中与停车中。 |
| 🟠 严重 | §6 验收标准 | 验收标准写“体验顺畅”,不可测。 | 改为四要素表格:前置条件 / 操作 / 期望结果 / 异常处理。 |
| 🟡 一般 | §5 界面元素表 | “保存”按钮缺少 disabled 条件。 | 补充未修改角度时 disabled,修改后 enabled。 |
| 🟡 一般 | §5 界面元素表 | 缺少调节失败提示。 | 补 Toast 文案与重试入口。 |
| 🟡 一般 | §7 数据指标 | 只列点击率,没有列调节完成率。 | 增加完成率与失败率作为上线验证指标。 |
| 🟢 建议 | §1 背景 | 背景段过长,可拆成“现状/问题/机会”。 | 改为三段式摘要。 |
| 🟢 建议 | §8 附录 | 术语“Modal”和“弹窗”混用。 | 统一为“弹窗”,首次出现可括注 Modal。 |

## 六维度逐项检查

| 维度 | 结果 | Finding 数 | 最高严重度 | 说明 |
|---|---|---:|---|---|
| 证据与依据 | FAIL | 1 | 🔴 致命 | 核心安全价值为 E 级证据 |
| 逻辑一致性 | PASS | 0 | — | 目标与主流程基本一致 |
| 边界覆盖 | FAIL | 2 | 🟠 严重 | 驾驶状态和失败态缺失 |
| 用户体验 | FAIL | 2 | 🟡 一般 | 反馈与按钮状态需补齐 |
| 技术可行性 | PASS | 0 | — | 未发现明显不可行承诺 |
| 商业合理性 | FAIL | 1 | 🟡 一般 | 指标缺少完成率 |

## 终审建议

- 建议:修订。
- 必须修复:核心价值证据、驾驶状态边界、可测验收标准。
- 可延后优化:背景结构和术语统一。
- 复审触发条件:完成上述必修项后,重新走 PRD 审查模式。
