# Dewu HIFI Four Tab Anatomy

本文件沉淀四个底部 Tab 定位页的页面记忆。它不是 HTML 模板绑定关系，而是模块、布局、密度和视觉原则的可迁移规范。

## Usage

当用户要求“请生成四个tab定位下的页面（总共四个），全部高保真。”或类似四 Tab 高保真定位页时，必须读取本文件。

生成其他 Dewu 页面时，也应按本文件抽取相关 surface 的模块原则。例如商品详情继承购买页的商品图片、价格、信任背书和 CTA 逻辑；个人设置页继承 `我` 页的 dashboard 密度和工具型信息组织，但不复制四 Tab 页面。

## Global Shell

- 使用截图证据坐标：单屏截图为 `1179x2556`，归一化为 `393x852 CSS px @3x`。长截图宽度仍按 `393 CSS px`，高度按滚动内容高度记录。高保真截图吸收默认让 `.phone-screen` 内部等效 `393x852`；外层手机壳/展示 rail 不得压缩内部坐标。
- 长截图必须按固定 viewport 加真实可滚动 `.scroll-content` 和内层 `.scroll-inner` 建模；不要把长内容缩放进一屏，也不要把超长内容裁切在不可滚动容器里。
- 若只是普通 Dewu HIFI 而非截图级复刻，可使用接近 `390x844` 的展示壳，但仍必须保持内部模块比例和无横向溢出。
- App chrome 退后：状态栏、搜索栏、频道栏、底栏都要克制，内容图像和业务模块承担视觉重量。
- 截图级复刻必须保留顶部居中 `得物App` App chrome。
- 底栏固定四项：`得物 / 购买 / 探索 / 我`。active 仍为黑色/`--n140`，不使用 Teal。
- 底栏 icon 是 stroke-only 线框，不用 emoji、填充块、CSS pseudo icon。
- 页面应像真实 App 截图：高密度、真实图片、白/浅灰 surface、细分割线、少量 Teal 强调。
- 字体、字号、行高、换行、截断、可见行数、可见文字、模块 top/height 和间距必须跟随上传截图；这些是设计事实，不是可自由发挥的装饰。
- 手机内部不得出现横向滚动条；右侧 badge、红点、箭头和头像不得用负定位撑出容器。

## 得物 Tab Anatomy

目的：社区推荐信息流。

结构：

- 搜索区：品牌/搜索/拍照入口，整体高度约 60px。
- 顶部频道：`推荐 / 极光街 / 运营活动 / 灵感 / 关注 / 穿搭`，推荐页 active 必须是 `推荐`。
- 频道后直接进入双列瀑布流，不插入品牌背书 chip、热帖 chip 或功能捷径行。
- Feed 卡：真实图片为主，标题最多两行，底部为头像/作者/统一 thumbs-up 点赞。
- 下滑后的 Feed 仍保持同一模块语言：双列瀑布流、图片自适应高度、视频卡右上角播放标识、标题 2 行、meta 单行。

视觉原则：

- 图片高度可以错落，避免统一卡高造成空白。
- 点赞图标全屏统一一种，不混用 heart。
- 不添加 `AUTH`、`NEW` 等截图没有的角标。

## 购买 Tab Anatomy

目的：交易和商品发现。

结构：

- 搜索区：搜索框主导，不需要大品牌 title。
- 交易频道：`推荐 / 潮玩 / 男装 / 美妆 / 鞋类 / 女装 / 三 分类`，最后一项必须带菜单图标感。
- 频道宫格：约 10 个入口，图标可以是线框/小图，但需要像真实入口，而不是纯文字。
- 信任背书行：可出现 `先鉴别后发货的开创者` 等交易信任信息。
- 商品区：双列商品卡，真实商品图/品牌图，价格、付款人数、标签信息密集但克制。
- 下滑后的商品流继续使用购买 surface 语法：白底商品图、15px 标题、13px 价格/付款人数、标签/评分/关注信息压缩在商品卡内部。

视觉原则：

- 购买页不是社区 feed，不能复用得物推荐的作者/点赞卡片结构。
- 价格使用中性色或受控样式；不要做大红促销页面。
- 商品图、品牌图和频道图决定页面真实感。
- 搜索区、频道栏、宫格、信任背书和商品卡必须按截图保持紧凑节奏；不能只校验模块数量。

## 探索 Tab Anatomy

目的：工具入口和消息中心。

结构：

- 页面标题为 `探索`，顶区简洁。
- 主体为工具入口列表或分组卡：`消息中心 / 鉴别服务 / 玩一玩 / 买卖闲置 / 得有钱·借钱`。
- 消息中心可出现红色数字 badge，例如 `3`。
- 每行包含标题、说明、右侧图形/箭头/红点，不做瀑布流。

视觉原则：

- 探索页更像工具 dashboard，密度高但模块清楚。
- 红色只用于 badge 或提醒点。
- 每行入口有明确业务动作，不写泛泛描述。

## 我 Tab Anatomy

目的：个人中心和工具 dashboard。

结构：

- 顶部为深色/Teal 氛围资料区，包含头像、昵称、等级、性别/状态、获赞与收藏、关注、粉丝。
- 昵称必须来自 Dewu 昵称池；截图级基线默认 `道u_5dbd337a7a...`，字号约 18px，不得放大成 profile 大标题。
- 资料区下方第一张卡为创作中心，包含数据、收益、活动、免单等创作者入口。
- 订单模块必须是五项：待付款、待发货、待收货、评价、退款/售后。
- 资产模块必须包含：想要、我有、足迹、关注。
- 后续工具模块至少包含：钱包、省钱神券；钱包是四列纯数字/文本资产摘要，不使用入口图标。
- 下滑后的个人中心必须继续包含 `出售` 商家状态模块和 8 宫格服务入口；这些是可复用 dashboard module，不是一次性 demo 内容。

视觉原则：

- `我` 页是工具型 dashboard，不是内容 feed。
- 模块卡片要密集但留出 8px 左右间距；避免大卡片套小卡片。
- 模块主标题约 16px；`钱包`、`省钱神券`、`出售` 等不能用 18-20px 大标题。
- 钱包、省钱神券、出售和服务宫格都应按截图紧凑堆叠；不得为了撑满长截图而增加空白、拉高模块或拉大 row gap。
- 数据和入口文案要像真实 App：有数字、有状态、有“全部 ›”这类操作入口。
- 头像必须使用真实图片 URL、真实本地资产或用户提供图，不用纯渐变圆。
- 资料头、创作中心和订单 dashboard 不得歪斜、折叠或互相覆盖；这种布局问题必须在测试阶段失败。

## Transfer Rules

- 生成非四 Tab 页面时，不复制四个页面结构，只迁移对应 surface 的模块原则。
- 新页面如果属于交易链路，优先继承购买页的商品图、信任背书、价格密度和 CTA；不要继承社区 feed。
- 新页面如果属于个人中心子页，继承 `我` 页的工具型 dashboard、数据入口、浅色卡片和深色资料区语言；不要复用商品卡。
- 新页面如果属于工具/服务入口，继承探索页的列表入口、说明文案、badge 和箭头组织。
- 新页面如果属于社区内容，继承得物 Tab 的双列图片 feed、作者/点赞 meta 和顶部频道克制风格。
- 新页面如果属于社区内容详情，继承 Type 2 内容详情页语言：无底部 Tab、大图轮播 hero、返回/页码/分享 overlay、商品推荐条、作者关注行、正文话题、评论区和底部互动栏。
