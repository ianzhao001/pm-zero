# 升级与迁移

## 从 v0.2.0 升级至 v0.3.0

默认六阶段、分步流程与既有项目的冻结定义保持兼容，升级不会迁移项目、重置确认或自动切换快速模式。

1. 备份仓库外的项目数据，保留现有部署。
2. 更新发行源码，运行 `npm ci --no-audit --no-fund`，构建到新的外部目录，例如 `base-v0.3.0`；品牌部署沿用原品牌选择与外置私有包。
3. 诊断新部署，切换宿主配置并重启 MCP 服务或在新会话重新加载插件。
4. 用 `runtime_info` 核对实际运行版本与 `product-design-quick-v1` 支持，再恢复原项目或创建独立验证项目。

需要快速模式时新建项目并主动选择，路径为 **澄清 → 高保真 → Demo**。最多一轮五问、三个确认节点，图片按需且不限数量；跳过独立 MRD、设计风格和线框稿。既有项目不通过重新打开改为快速模式，快速项目也不在中途转换为标准模式。

如需回滚，切回保留的 v0.2.0 部署并重新加载。回滚运行包不会回退项目数据；v0.2.0 无法执行快速流程，应保留 v0.3.0 或其他支持该流程的部署用于快速项目。

## 从独立 Skill 快照迁移

旧公开版本的入口位于根目录 `design-forge/` 和 `dewu/`。当前版本使用完整基础组件和可选品牌包，通用入口位于 `skills/`，品牌源位于 `brand-packs/`，实际宿主加载构建后的独立部署。

1. 将用户自行修改的品牌规则、脚本和项目产物备份到仓库外。
2. 安装 Node.js 24+，在当前源码目录运行 `npm ci`。
3. 选择通用、得物或京东，构建到一个新的外部目录。
4. 将宿主旧 Skill 注册替换为新部署；不要同时注册两套入口。
5. 运行诊断，并用一个独立项目验证所需能力后再切换日常工作。

旧版品牌文件不是品牌 API v1 清单，需要按开发规范整理成外置私有包；不要直接覆盖新基础组件。原有产物与确认记录不自动导入为已验证项目。

v0.2.0 起保留公开仓 Git 历史。当前发行树移除了旧证据说明、内部路径和过程性示例，旧提交仍可能包含这些内容；升级不是历史清理操作。
