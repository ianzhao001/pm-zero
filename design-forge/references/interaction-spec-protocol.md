# Interaction Spec Protocol

- Status: active reference
- Scope: visual interaction spec and Demo conformance
- Source lineage: pm-zero native, informed by magi-product Demo discipline
- Publish scope: private-mirror

## Allowed Artifact Shapes

The interaction spec may be:

- Static HTML page with styling and no application logic.
- SVG.
- Mermaid flow diagram.
- A combination of the above.

Figma, Sketch, Axure, or other external design-tool artifacts may be reference materials, but they do not replace the pm-zero interaction spec.

## Directory Convention

Use:

```text
workspaces/<workspace>/interaction-specs/v<N>/index.html
```

or equivalent `.svg` / `.md` in the same version directory.

Each version must include `CHANGELOG.md`.

## Version Semantics

- `v1`: first confirmed spec.
- `v2`, `v3`, ...: iterations after user or reviewer feedback.
- A Demo cannot silently revise the main flow; it must trigger an interaction-spec version if main flow changes.

## Generation Ownership

The interaction spec is generated by the host Agent operating pm-zero. It is not treated as a user-external design drop-in unless the user explicitly frames it as input material.

## Demo Conformance Contract

The Demo must map to the confirmed interaction spec.

Strict conformance requires:

- Page structure corresponds to the spec.
- UI element list corresponds to the spec.
- Information architecture levels correspond to the spec.
- Every Demo must include an `element-mapping.md` table mapping spec elements to Demo elements.

## Demo-filled Legal Boundary

The Demo may fill secondary states not specified in the interaction spec:

- loading
- error
- empty
- disabled
- debounce interval
- timeout threshold

These must be labeled `Demo-filled` and backfilled into the next interaction-spec iteration if they remain product-relevant.

## Demo-filled Prohibited Boundary

The Demo must not fill or change:

- Main flow nodes.
- Key decision paths.
- Information architecture levels.

Changing any of these requires returning to the interaction-spec stage.

## PRD Linkage

PRD §5 element table and Demo `element-mapping.md` are mutual validation sources.
