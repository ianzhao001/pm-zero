# 分步产物工作流

本文件保留原流程的历史阶段与恢复语义；默认新项目使用[六阶段协议](six-stage-product-workflow.md)。不得把本文旧编号重写为新项目编号。六阶段细分模板只复用适用的步骤控制规则。

适用于新项目显式选择的 `product-design-stepped-v1`。沿用[八阶段协议](staged-product-workflow.md)的交付终点、静态材料、能力来源、审查、验证和阶段确认；本协议增加阶段内的独立产物与手动控制。旧项目继续自己的冻结定义，不自动转换或补造历史确认。

## 模板选择

采用分步流程时，先由用户选择项目类型（`new_product` 新产品、`iteration` 已有产品迭代、`feature` 局部功能）和交付深度（`lean` 精简、`standard` 标准、`full` 完整），在 `project_open(create: true)` 中同时传入 `workflow_id: "product-design-stepped-v1"` 与 `step_template: { project_type, depth }`。九种模板组合在创建时编译并冻结；第一版不在运行中换模板或自由重排。精简只合并准备材料，不降低独立审查、Demo 证据和阶段确认要求。

创建参数 `context` 绑定项目品牌（从运行包支持清单选择，缺省 none），须由实际安装包支持。分步 v1 将品牌与模板一起冻结，不能在后续准备、登记或重开时改品牌；原八阶段 S1 变更品牌的规则不适用于该流程。

## 产物与手动控制

以项目冻结定义和 `stage_prepare` 返回的候选步骤为准，不从本文或对话猜测步骤 ID。产品步骤标识为 `workflow_step_id`；Skill 的 `load_steps` 是同一次能力执行的加载顺序，两者不能混用。

1. 读取 `project_read(view: "resume")` 和当前 revision 的 `stage_prepare`。未选择步骤时返回 `await_selection`，没有可执行计划。展示当前候选及其输入、输出，等用户明确选择后调用 `step_select`，保留原始答复的 source/text。
2. 重新准备，只生成选中步骤声明的产物。每步使用独立文件，登记真实输入版本、执行来源和校验结果。文件存在或模型宣布“完成”均不等于完成登记或确认。
3. 产物齐备后停止，展示确切版本、文件路径、检查结果和未决项。`await_step_confirmation` 只等待用户确认当前版本；收到明确答复才调用 `step_confirm`，携带该步输出的准确 artifact_id/version/sha256，包括该步的审查产物。
4. 确认清除当前选择，展示下一步候选并停止。必须收到新的人工选择才调用下一次 `step_select`；不能把“确认当前版本”解释为“选择并执行下一步”。读取、恢复和整体计划授权均不能代替这两个分别记录的动作。
5. 阶段内所有步骤确认后仍须正式 `gate_confirm`。阶段确认不自动选择下一阶段的步骤。S6 多输出必须同时齐备，独立审查步骤仍须确切版本及独立作者；S8 保留原浏览器证据要求。

总览位于 `.pm-zero/step-overview.md`，由已登记事实派生；`project_read.step_progress` 返回模板、当前阶段、活动步骤、下一步骤与逐步状态及产物引用。总览删除后可重建，不覆盖产品目录原有文件，也不成为第二份事实来源。会话恢复仅展示停留位置、有效版本和可选动作，不主动续跑。


## 登记与来源

分步登记额外要求顶层 `workflow_step_id` 与 `execution.workflow_step_id` 都匹配当前选择。输出必须属于该步声明，输入绑定已确认的依赖版本，不能把其他步骤的源文件登记为本步产物。基础结构校验与用户确认分别记录；通过结构检查不宣称需求、设计效果或真实用户共识已获验证。

分步 `stage_prepare` 除 produce、review、await_confirmation、blocked、completed 外，还区分 await_selection 与 await_step_confirmation。只有当前已选择产品步骤返回可执行计划。只申报真实宿主能力，执行该步 load_steps 并保存实际回执；加载验证器不等于运行验证。不能借同阶段能力任务交接跨过步骤确认。

## 返工与恢复

分步项目先向用户展示冻结预览中的实际影响与保留范围，再以单独的 `change_apply.user_response` 记录对返工范围的确认。变更使实际依赖该版本的下游产物、步骤确认及相关选择失效，无关版本保留；用户不能把实际受影响的下游直接标为有效。变更应用后重新查看当前候选，仍须手动选择才能返工。

读取和诊断可重建派生总览，但不发布步骤选择或确认。遇到 revision 冲突先重新读取；不覆盖人工编辑，不静默放宽当前冻结模板的产物和确认条件。
