# 六阶段产品工作流

默认新项目用 `product-design-six-stage-v1`；主动选择细分流程才用 `product-design-six-stage-stepped-v1`。既有项目保留冻结快照、编号、范围和确认，不自动迁移。

## 阶段与范围

| 阶段 | 成果与能力交接 |
|---|---|
| S1 目标与场景 | 用途、用户、场景、平台、约束、成功标准与终点；澄清和发现联合完成 |
| S2 MRD | 业务建模→MRD；范围、核心路径、非目标、规则和假设，作为后续范围源 |
| S3 视觉方向 | 方向→配色字体；风格板、主视觉、色板与字体，品牌复用仍交付本项目应用 |
| S4 线框与交互 | 信息架构、线框、静态交互规格与 design_model；稳定页面/元素 ID |
| S5 高保真 | 继承 S3/S4 的核心静态视觉稿，保留范围与模型映射 |
| S6 Demo | 继承确认设计的可操作核心闭环、模拟边界与浏览器证据 |

终点默认 S6；“线框与交互”到 S4，仍完成前序；不产 PRD。已回答问题直接复用。默认正常主流程，导航、返回、关闭和反馈照常完成；空态、异常态和对应测试仅按用户明确请求纳入范围源，品牌参考不自动扩大范围。

## 推进与交付

先用 `runtime_info` 核实安装版本、流程、品牌和能力；`project_open` 显式指定 workflow/context，品牌绑定 S1，变更须正式重开。工具不足可讨论但明确阻塞，不以源码或独立草稿冒充登记成果。只申报实际宿主能力；不偷载未登记 Skill、不静默切中性或 legacy。

按当前 revision 调 `stage_prepare`，仅执行当前 `load_steps`。阶段内制作、检查、必要独立审查、修订自动衔接，不预做后续阶段。普通流程每阶段一次用户确认，共六次；能力交接不增加步骤选择或单份确认，素材先完成再整合。

S2/S4/S5/S6 全部必需产物需独立同版本审查；S4 线框、规格、模型联合放行。来源登记、资产回执与用户答复遵循共同加载的[执行契约](stage-execution-contract.md)；自检、结构校验与真实用户验收分开报告。

每段先给短结论，再按需展示图稿、版本、选择、检查结果与待确认项；JSON 模型及完整报告作附件，不能当用户主入口。交付给出绝对路径，等待当前版本明确确认后才 `gate_confirm`；达到所选终点即停止。

## 静态材料

S1–S5 用 Markdown、PNG 或无脚本 SVG，不交付可操作原型。HTML 仅用于静态导图，不承载产品交互、不替代图稿或登记为 Demo。线框用清晰网格、灰度、中文，正文≥16px、注释≥14px，交付单屏及总览 PNG；手绘仅按用户偏好。渲染后检查重叠、裁切和可读性。

## 修改、恢复与细分

先 `change_prepare` 展示目标、保留范围和影响，已有范围授权后 `change_apply`，扩大范围重新讨论；禁止覆盖已确认源文件。失效按实际依赖传播，范围变更回 S2，目标/终点变更回 S1。恢复用 `project_diagnose`/resume，仅取有效版本、待确认项、阻塞及必要原始记录；不自动确认。验证范围取自已确认设计，未执行项标 skipped/pending。

用户主动选择细分时冻结“项目类型 × 深度”模板，并读取[分步协议](stepped-product-workflow.md)。逐步选择、独立文件、确认、恢复与返工沿用该协议，编号使用本流程 S1–S6，联合结构阶段为 S4、Demo 为 S6；额外步骤确认只用于细分模式。
