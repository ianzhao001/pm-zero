# Advocacy Dimensions

## Evidence

- Which claims are tied to existing requirements, prior decisions, or observable artifacts?
- Which assumptions are honestly labeled and therefore usable for staged progress?
- Which facts are strong enough to preserve during revision?

## Logic

- Where does the problem-to-solution chain make sense?
- Which decisions reduce ambiguity for downstream work?
- Which tradeoffs are explicit enough to be reviewed rather than guessed?

## Boundary

- Which scope boundaries prevent uncontrolled expansion?
- Which state or edge case coverage is already useful?
- Which limitations should remain visible instead of being optimized away?

## UX

- Which path is clearest for the target user?
- Which interaction pattern lowers effort or decision load?
- Which labels, hierarchy, or feedback loops should be preserved?

## Feasibility

- Which parts can be implemented with current tooling and project structure?
- Which choices avoid unnecessary dependencies?
- Which simplifications keep the next step executable?

## Business

- Which part of the output best supports the product positioning?
- What opportunity is lost if the proposal is rejected?
- Which decision creates learning value even before full implementation?
